## 5. Security assessment (credentials & local routing)

- Provider secrets stay server-side in Hub (encrypted connection rows). Satellite apps receive metadata only; tm-tools/tm-studio use app-secret or device credential to call Hub relay.
- Electron: `ai-secure.cjs` uses OS keychain (`safeStorage`) with idempotent encrypt / tolerant decrypt; degrades to plaintext if unavailable. Good boundary; tests exist.
- tm-studio gateway runs in main process, keys never touch renderer; audit log to userData/logs.
- Risk: `is_shared` must not be treated as authorization (plan §7.2) — needs audit of grants usage.
- Risk: mode is currently inferred from base URL / connection ownership rather than an explicit `hub|app|local` field (plan §6.2, §9.3) — must add explicit mode.

## 6. Recommended package boundaries

Per plan §2.1, start with `@tm/types`, `@tm/validators`, `@tm/utils` (low coupling, runtime-agnostic), then `@tm/ui`, `@tm/nuxt`, `@tm/ai-client`. `tm-hub-client` stays separate (Control Plane SDK). TMCut engine (`tm-studio/packages/core`) stays in place until separate decision. Do not create a mega package. Browser/server/Electron boundaries must be enforced (subpath exports like `@tm/utils/browser`, `@tm/utils/node`).

## 7. Hybrid AI migration plan (concrete)

1. Add explicit `mode: 'hub' | 'app' | 'local'` to connection metadata (tm-hub schema + satellite caches).
2. tm-hub: restrict relay to Hub-managed connections only; add explicit grants (app, connection, operations, model restrictions) with revoke/expiry/audit.
3. tm-tools: implement App AI Gateway routing adapter; FreeLLMAPI as `local` mode executed by local runtime (Electron main / local server), never via Hub relay; keep Hub catalog + Hub-managed connections.
4. tm-studio: same gateway; keep Electron secure vault; keep TMCut core untouched.
5. Catalog sync with version/cursor; idempotent; metadata only (no credentials); model visibility != inference permission.
6. Localhost failure guard: hosted Hub never receives localhost URLs; show clear local-offline errors; no silent fallback local→cloud without consent.
